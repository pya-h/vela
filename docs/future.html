🧠 Memory, Regions & Resource Safety (Open Extensions)

Move-Only Owning Pointers (own ^T@r) Idea

Scoped regions free everything in r at block exit. To reclaim a single heap object early inside a long-lived region without waiting for the block to close, an explicit owning pointer own ^T@r would combine linear move checking (at most one owner, moved on assignment/pass) with single-object free when that owner leaves scope or calls an early release helper.

Scope Guards: defer & Static Leak Checking Idea

Regions already close opened Files automatically on scope exit, but general non-region resources (external sockets, OS handles, locks, temporary state cleanup) have no general lexical cleanup statement. 

task copy_log(path: text@r) -> nothing ~ FileError
    fixed handle = open_raw(path) { failure err <- fail err }
    defer handle.release()
    process(handle) { failure err <- fail err }
fi

Paired with static leak checking, resource-returning types could require every control-flow path to pass, consume, or defer-release them.

Read-Only Borrowed Views & Array-to-Slice Conversions Low

  • Array-to-slice & @view: Today [1, 2] never becomes [int]@r directly (you write [1, 2, ...] at r or new [int](xs) at r). Candidate improvements: xs.slice() at r, p^[..] to view a heap array pointer without copying, and read-only view parameters (xs: [int]@view) able to borrow stack arrays or slices safely without growing them.
  • Non-reusing slices: A separate append-only slice flavor that never reuses storage freed by del() so older slice views/copies never observe overwritten slots (at higher memory cost).
  • Niche-optimized nullability: Extending maybe ^T's zero-overhead null representation to maybe bool, small kinds, and non-zero numeric invariants.

Shallow Sharing, hold Bindings & Exclusive Locks hold Shipped Shallow Views Open

Vela now ships all four binding modes — fixed, bind, hold (and hold&: reassignable place with deeply immutable contents), and flex — alongside := default-region initialization. Remaining open questions focus on intentional shared/read-only views without deep .copy():

  • A deliberate shared/read-only view vs. borrowing references without full .copy().
  • Whether a runtime check or single-writer lock marker (flex x!: int) should detect concurrent/unexpected alias writes if shallow sharing is ever exposed.

Start-Time Values & Static/Global Region Extensions Open

region global(N) is built for fixed static data declarations, while shared fields and startup decorators still cannot allocate dynamic slices, joined text, or pointers before main runs (Decorators). Possible follow-ups:

  • Allowing new T(...) at global, joined text at global, and bounded slices in global (checked against its declared byte cap) so startup registries and shared fields can store built strings/tables safely.
  • Or per-shape shared region pool arenas scoped exclusively to one shape's methods.

🌐 Concurrency, Actors & Commitments (Remaining Ideas)

Channels, actors, the M:N scheduler, select ... otherwise ... fi, and <<- / ->> operators are all implemented (see Concurrency). The ideas below remain unbuilt:

Zero-Copy Chan[own region] Idea

Handing ownership of an entire isolated region across a channel or actor mailbox in O(1) without deep-copying regional graphs, invalidating all sender handles to that region at send time.

Commitment Extensions Idea

Commitment[T], rush, .then()/.recover(), and structured auto-cancellation have landed (Commitments). Remaining extensions — collection combinators, actor ask, deadlines, and non-blocking I/O — are detailed in Unlocked Next Steps below.

Actor Extras: Supervision & Mailboxes Open

Configurable bounded mailbox overflow strategies (drop-oldest vs. backpressure), actor lifecycle restart hooks/supervision trees, and runtime scheduler worker metrics.

Multi-Core Region Isolation Proofs Open

Explicit rules for running reactive events safely when triggered from concurrent actor contexts, and synchronized global/shared state access.

🧩 Methods, Generics, Groups & Lambdas (Remaining Extras)

Method Extensions Idea

  • Computed property members: No-argument read-like members whose answer is cached until a field they read is modified by an alters method.
  • Ordered kind helpers: Automatic .next(), .prev() (returning maybe), .first, and .last on payloadless enum-like kinds.
  • Methods allocating in their value's region: Passing @this implicitly to alters methods so a shape can grow its own .items.add(...) slice internally rather than forcing callers to pass r explicitly.
  • Explicit generic arguments on method calls: Allowing b.mapped<text>() where return types cannot be inferred solely from arguments.
  • Extension methods & custom ==/~=: Letting shapes override similar(other: This) -> bool for custom deep equality/cycle-safe structural checks, and deciding whether foreign modules may ever attach non-priv methods.
  • Shared members inside generic shapes: Per-instantiation vs. shared-across-all-T fields on Box<T>.

Type Groups: Nested Loops, Type Matching & Region Groups Idea

  • Loops inside loops over one group: each v: A in args naming the turn's type parameter explicitly so nested iteration over the same group does not collide on P.
  • Matching a generic/group value by type (match v?): Allowing compile-time pruned branches over polymorphic group values (case int n, case [int] xs read-only view, case (int, float) a, b) where currently only v.type text exists.
  • Writing (P...) as a standalone binding tuple type and allowing regions inside a type group (today regions must be named beside P...).

Dynamic Pattern Values (Existential Dispatch) Idea

Patterns currently constrain generic type parameters statically (<T: Shaped>). Adding dynamic existential pattern values ([Shaped]@r) would pair a region-scoped pointer with a compiler-generated vtable so heterogeneous shapes can live in a single slice and downcast via match.

Generics, Lambdas, Iterators & Operators Follow-Ups Idea

  • Optional region parameters on generic shapes: Skipping unused region parameters when Box<T> is instantiated with region-free types like Box<int>.
  • Operator overloading extras: Mixed-type operands (Int512 + int), custom ==/!= value equality, ** overloading, and bitwise operator overloading.
  • BigInt family expansion: Adding unsigned UInt512, Int128/UInt128, Int256/UInt256, Int1024/UInt1024, bit shifts, pow_mod, isqrt, and gcd in std/int512 (or sibling modules).
  • Lazy iterator Phase 2: Short return/variable types for uncollected chains, compiler loop fusion into a single C loop, [@r] capturing lambdas inside iterator adapters, generators/lazy streams, and additional sources/adapters (ranges, lines, flat_map, chunks, windows, rev).
  • Lambda & task-value extras: Capturing field/array places ([flex& p.x, @r]), growing/shrinking captured slice copies safely, cloning held [flex @r] blocks explicitly, devirtualizing known task values, naming generic tasks (first<int>) and instance methods (Point.area) as task values, and multi-return task value types.
  • Wrappers & decorators extras: Wrappers on methods of generic shapes (shape Box<T>), decorators on shapes once shapes can be passed as values, and compile-time static registry tables for startup decorators.
  • Derive service: Beyond built-in .str() and ~=, opt-in derive for hashing, cloning, and fast value equality.

⚡ Performance, Macros & Low-Level Control

Macros with Args & comptime Idea

Hygienic value-taking macros (task #SQUARE(x) evaluated once per arg), using macros in array type lengths ([int#SIZE]), type macros (#Vec2 = (float, float)), constant folding of pure tuples, and full compile-time execution (comptime tasks & comptime bench).

SIMD Vector Types Idea

Explicit vec4f/vec8i register types for predictable lane arithmetic, reductions, and masks mapped cleanly to target intrinsics or scalar fallbacks in C11.

Controlled Shape Layout Idea

packed, aligned(64), and hot field-grouping layout directives lowered to C11 _Alignas / packed attributes for systems, binary formats, and cache tuning.

Typed Inline Assembly Idea

Checking register constraints and clobbers against Vela types in explicit asm(...) blocks for kernel, crypto, and low-level drivers.

Monomorphization & Representation Idea

Deduplicating identical generic C instantiations across modules, explicit inline vs type-erased shared generics hints, and tagged-pointer optimization for small kinds.

Bitwise Operations Planned

Explicit bit masks, shifts, xor, and complement (either C-style operators &, |, <<, >> with defined overflow/shift bounds, or builtin methods like .band()/.shl()).

🎨 Bold Type-System & Syntax Directions

  • Algebraic Effects: Explicit lexical effect declarations, perform, and handle ... resume blocks without implicit effect inference.
  • Typestate & Session Types: Phantom generic state tags (e.g. File<Open> → File<Closed>) and affine single-use rules for protocol safety.
  • Refinement & Distinct Types: Compile/runtime-checked constraints (int where n > 0), parameterized type aliases (alias BoxList<T>), and distinct newtypes so IDs aren't mixed with raw ints.
  • Flattened Inner-Kind Matching & Case Guards: Matching nested errors directly (e.g. InputError.NotANumber without two nested match blocks), range cases & match on ints/chars, and boolean guards (case Circle r when r > 0.0).
  • Shipped — Postfix ! & !> Error Propagation (and Future Method-Projection Sugar): Early failure propagation (call()!, call()!.method()) and error-mapping pipelines (!>, !>>, inline failure, and e -> expr mappers) have now shipped using ! (preserving ? for decorators and dynamic tuple queries). A small future ergonomic addition would be shorthand projection (such as call() !> .context("...")) alongside the existing failure and e -> expr forms.
  • Syntax & Statement Cleanup: Requiring statements to end at a newline while permitting multiline expressions inside ( ) / { }; rejecting multiline raw string literals; named call arguments (resize(width: 2.0, height: 3.0)); inclusive ranges (0..=10); explicit round/floor; each i, v in xs indexed slice loops; mid-loop typed failure exits; assert(...); and single-item tuple syntax.

🚀 Unlocked by Recent Features (Commitments, Actors, Channels & Events)

Now that Commitment[T], rush, M:N scheduled actors, bounded Chan[own T], select, region splicing, and guarded reactive events are live in Vela, several higher-level capabilities fit the language naturally without inventing unrelated machinery:

Actor Request–Reply (ask → Commitment[R]) Idea

Allowing an actor handler to declare a return value (on Fetch(id: int) -> text) and calling it with rush a.Fetch(1) to yield a Commitment[text]. Under the hood the caller allocates a single-shot reply handle, so callers get type-safe <<-, select timeouts, and .then()/.recover() chains on actor state without manually wiring reply channels.

Dynamic Fan-Out & Collection Combinators Idea

select currently handles a fixed set of arms known at compile time. With linear Commitment[T] + region splicing in place, runtime helpers such as await_all(cs), await_any(cs) (cancelling losers automatically), and parallel each item in xs rush ... fan-out can process variable-length slices (e.g. batching Client.fetch requests or tile rendering) while splicing all worker regions into a single caller region.

Hierarchical Deadlines & Structured Timeouts Idea

Propagating a deadline through vela__rt__current_commitment alongside cancellation (cancelled() / remaining_ms()) lets a parent timeout automatically cap inner rush tasks, select case after ms arms, and std/web request handlers without plumbing timeout parameters through every helper.

Non-Blocking OS Event Reactor (epoll/kqueue) Idea

Currently, blocking socket/file I/O inside rush (such as std/web serve_concurrent or Client.fetch) occupies a pool worker or helper thread until completion. Integrating a non-blocking OS I/O poller into the M:N scheduler lets paused tasks yield their OS thread and resume only when descriptors become readable/writable.

Channel Iteration & Concurrent Pipelines Idea

Connecting lazy iterators, channels, and commitments: each msg in ch draining a Chan[T] cleanly until close, bounded worker pools fed by a shared channel and emitting per-item commitments, and reactive event hooks safely pushing immutable notifications into actor mailboxes.

Indirect & Value-Isolated rush Tasks Idea

Extending rush beyond direct named tasks to support plain stateless lambdas and deep-copied immutable closures ([fixed @r]), while preserving the invariant that no mutable caller reference or alters method can cross into concurrent execution.
