Vela.

A minimal, safe, fast systems language with a fresh face.

What is Vela?

Vela is a small systems programming language designed to be minimal like Go, safe like Rust, and expressive like modern functional languages — without the bloat. It has one clear way to do things: one kind of function, one kind of record, one kind of sum type, and explicit memory management without a garbage collector.

Vela compiles to C through a Rust-based compiler, so it runs anywhere C runs and inherits its performance while keeping the source language tidy and opinionated.

Philosophy

  • Minimal surface. No classes and structs. No interfaces and traits. Just shapes, kinds, and tasks.
  • One way to do it. Immutability by default with bind; mutation explicitly opt-in with hold.
  • Safe by design. Static typing, exhaustive pattern matching, and explicit ownership via owned pointers.
  • Beautiful syntax. Words over symbols, clean blocks closed with fi, and no semicolons.
  • No GC. Manual memory management with new and free, or stack allocation where possible.

Hello, Vela

# A tiny Vela program
task main()
    show("Hello, Vela!")
fi

Compile and run with:

cargo run -- examples/hello.vela -o hello
./hello

Types

  • int — 64-bit signed integer
  • float — 64-bit floating point
  • bool — true or false
  • text — UTF-8 string; == compares contents
  • unit — the return type of a task that returns nothing; it has no values, so it can't be the type of a variable, parameter, or field
  • ^T — owned pointer to T; none is the empty pointer
  • User-defined shapes and kinds

Syntax Overview

Every block — a task, shape, kind, when, loop, each, or match — closes with fi. Each statement goes on its own line; there are no semicolons.

A statement is a binding, an assignment, a block, send, free, or a task call. Any other expression on its own line would do nothing, so it is an error: x == 1 alone reports the result of '==' is unused; use '=' to assign.

Tasks

Functions are called tasks. The return arrow is required only when returning a value.

task add(a: int, b: int) -> int
    send a + b
fi

task greet(name: text)
    show(name)
fi

A task that returns a value must send one on every path: the compiler rejects a task that could reach its end without sending. A when counts only if both branches send, a match only if every case does, and a loop never counts, since its body might not run. A task without a return type uses a bare send to return early. 

task sign(x: int) -> int
    when x < 0
        send -1
    fi
    send 1               # without this line: task 'sign' can finish without sending a value
fi

Every program starts at task main(), which takes no parameters and returns nothing.

Bindings

bind creates an immutable binding. hold creates a mutable variable.

bind pi = 3.14
hold count = 0
count = count + 1

A variable lives until the block that declares it closes. Vela has no shadowing: inside a task, a name cannot be declared again while another variable with that name is visible (including parameters). Separate blocks, such as the two branches of a when, may reuse a name. 

when ready
    bind label = "go"
    show(label)
else
    bind label = "wait"   # fine: a different block
    show(label)
fi
show(label)                # error: unknown variable 'label'

Numbers

Arithmetic (+ - * / %) works on int and float. If either operand is a float, the result is a float; two ints give an int, with division truncating toward zero. % on floats keeps the sign of the dividend. Comparisons (< <= > >=) require both sides to have the same type. Number literals are decimal digits with an optional fraction (42, 3.14); there are no exponent or hex forms, so 1e5 is an invalid number. 

show(7 / 2)       # 3
show(7 / 2.0)     # 3.5
show(5.5 % 2.0)   # 1.5

Text, Output, and Logic

Text literals use double quotes and support the escapes \n, \t, \r, \\, \", and \0. A # starts a comment that runs to the end of the line. show is the only builtin task: it prints an int, float, bool, or text followed by a newline (floats with up to 6 significant digits).

Logic uses words: and, or, and not work on bool, and and/or skip the right side when the left side decides the result. == and != work on numbers, bool, text (by contents), and pointers; both sides must have the same type, except that none compares with any pointer. 

# greet the user
show("say \"hi\"")       # say "hi"
show(2.0 / 3.0)            # 0.666667
show(1 < 2 and not false)  # true
show(1 == 1.0)             # error: expected type int, got float

Shapes

Shapes are Vela's only composite data type — like structs, but the only one.

shape Point
    x: int
    y: int
fi

bind p = Point { x: 10, y: 20 }
show(p.x)

A shape literal must give every field exactly once, in any order: Point { y: 20, x: 10 } is the same value. A shape may also have no fields (Marker {}).

Shapes and kinds can be used before they are declared. A type cannot contain itself by value, since its values would be infinitely large, but it can point to itself: 

shape Node
    value: int
    next: ^Node            # ok: a pointer
fi

shape Loop
    inner: Loop            # error: 'Loop' contains itself by value
fi

Assigning to a field requires the variable to be a hold; task parameters are immutable.

hold q = Point { x: 1, y: 2 }
q.x = 5                    # ok
p.x = 5                    # error: p is a bind

Kinds

Kinds are tagged unions with exhaustive pattern matching. Each case binds the variant's payload fields in order; the bindings are visible only inside that case, so different cases may reuse names. A kind value has no fields of its own (s.radius is an error): match is the way to read a payload. 

kind Shape
    Circle(radius: float)
    Rectangle(width: float, height: float)
fi

task area(s: Shape) -> float
    match s
    case Circle r
        send 3.14 * r * r
    case Rectangle w h
        send w * h
    fi
fi

A variant can have no payload. Write its value as just its name, with or without parentheses; its case binds nothing. 

kind Light
    Red
    Green
    Dimmed(level: int)
fi

bind a = Red
bind b = Green()          # same as Green
bind c = Dimmed(3)

Names

A name starts with an ASCII letter and continues with ASCII letters, digits, and _, but cannot contain __ (two underscores), which the compiler keeps for its own C names. Words that mean something in C, such as int, default, or stdout, are ordinary names in Vela.

Tasks, shapes, kinds, and variants share one namespace: no two of them can have the same name, even across different kinds, and none can be named like a builtin (int, float, bool, text, unit, show). Every type you write must be a builtin, a shape, or a kind. A variable can't take a variant's name, so a bare Red always means the variant.

Control Flow

when x > 0
    show("positive")
else
    show("non-positive")
fi

loop count < 10
    show(count)
    count = count + 1
fi

each i in 0..5
    show(i)
fi

each counts from the start of the range up to, but not including, the end. Both ends are evaluated once, before the first iteration; the loop variable is immutable. A range such as 0..5 is not a value: it can only appear in each.

Memory

Owned pointers are explicit and manually freed. No garbage collector.

bind p: ^int = new int(42)
show(p^)
p^ = 43                    # writing through a pointer is allowed, even from a bind
free(p)

none is the empty pointer. It fits any pointer type and can be compared with any pointer, but on its own it has no pointer type, so a binding initialized with none needs one written out. 

hold next: ^int = none
when next == none
    next = new int(1)
fi
bind q = none             # error: cannot infer the type of 'q' from none
Note: Vela intentionally keeps memory management simple. There is no borrow checker; ownership is manual, like C but with clearer syntax. Use new/free with care.

Complete Example

task fib(n: int) -> int
    when n < 2
        send n
    else
        send fib(n - 1) + fib(n - 2)
    fi
fi

task main()
    each i in 0..10
        show(fib(i))
    fi
fi

Building the Compiler

The Vela compiler is written in Rust and generates standard, portable C11, which it compiles with the C compiler named by the CC environment variable (cc by default). CC may include arguments, as in CC="ccache gcc". 

cargo build
./target/debug/vela program.vela -o program
CC=clang ./target/debug/vela program.vela -o program

To see the generated C code:

./target/debug/vela program.vela --emit-c

Errors point at the exact place in your source:

program.vela:3:10: error: unknown variable 'missing'
 3 |     show(missing)
   |          ^

To run the test suite (requires a C compiler, $CC or cc):

cargo test
CC=clang cargo test

Tests are plain Vela programs: tests/run/ holds programs with their expected output, tests/fail/ holds programs the compiler must reject, and every file in examples/ is checked against tests/examples/. The C generated for run tests and examples must also compile as strict ISO C11 with no warnings (-std=c11 -pedantic-errors -Wall -Wextra -Werror). Rust tests in tests/*.rs cover the command line, the library's build pipeline, and the lexer.

The compiler is also a Rust library, vela, so tools can use the language without copying it: vela::driver checks and builds programs exactly as the vela command does (and can keep a partly checked program for editors), vela::lexer::highlight splits source into tokens without stopping at errors (for editors), and lexer::KEYWORDS and ast::BUILTIN_TYPES list the language's reserved words and types.

The repository is a Cargo workspace: the compiler is the default member, and Vela Studio's code lives under ide/: ide/analysis is the engine behind highlighting, diagnostics, outline, go-to-definition, completion, and hover, built on the compiler; ide/wasm compiles it to WebAssembly so it runs in the editor page; ide/server is the vela-studio program, a local server for files, builds, runs, and terminals; and ide/web is the editor page (TypeScript, CodeMirror). Plain cargo build and cargo test cover only the compiler, which has no dependencies; add --workspace to include the IDE crates. 

cargo test --workspace

The editor page needs Node.js and the wasm32-unknown-unknown Rust target (rustup target add wasm32-unknown-unknown). Build it, then start vela-studio on a folder. It serves that folder on 127.0.0.1 only, prints an address with a secret token, and opens it in the browser (--no-open just prints it). F5 saves and runs the open file in the Output panel, compiler errors are listed under Problems, and Ctrl+` opens a terminal in the folder. 

npm --prefix ide/web install
npm --prefix ide/web run build         # the analysis module and the page
cargo run -p vela-studio -- examples

The page's own checks: unit tests, type checking, and end-to-end tests in Chromium against a real server.

npm --prefix ide/web test
npm --prefix ide/web run typecheck
npm --prefix ide/web run e2e           # set CHROMIUM if it isn't /usr/bin/chromium

To lint the compiler (or everything, with --workspace):

cargo clippy --all-targets

The compiler's own code may not use unwrap(), expect(), panic!, or unchecked indexing (enforced by lints in Cargo.toml), so problems are reported as errors instead of crashes. An error starting with internal compiler error means a bug in the compiler itself, not in your program.

Design Notes

  • Vela is intentionally small. It is not meant to replace Rust or C, but to explore how little syntax is needed for a safe, compiled systems language.
  • Memory is manually managed to avoid GC complexity while keeping the implementation approachable.
  • The compiler generates readable C, making it easy to debug and interoperate with existing C code.
  • Syntax uses keywords over punctuation to keep source code friendly and self-documenting.

Vela — designed and implemented as a minimal systems language experiment.
